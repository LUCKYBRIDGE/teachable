# 테스트 계획

## 1. 테스트 목표

데스크톱에서만 동작하는 데모가 아니라 학교 복도에서 장시간 사용할 수 있는 태블릿 웹앱을 목표로 한다.

## 2. 우선 실기기

보유 기기 기준 우선순위:

### AI Camera 후보
- Galaxy Tab S9 FE 우선

### Display 후보
- Galaxy Tab S6 Lite
- Galaxy Tab S5e 또는 실제 보유 기기 확인 후 추가

정확한 모델 세대와 Android/Chrome 버전은 실기기 테스트 단계에서 기록한다.

## 3. 기능 테스트

### Camera
- 권한 최초 허용
- 권한 거부
- 전면/후면 전환
- 화면 회전
- 잠금 후 복귀
- 탭 백그라운드 후 복귀
- 카메라 stream 중복 생성 여부

### Model
- 정상 로드
- 모델 파일 404
- weights 로드 실패
- 모델 변경
- 이전 모델 rollback
- model cache 갱신

### Prediction
- neutral
- 각 목표 동작
- 동작 진입
- 동작 해제
- 유사 동작 전환
- threshold 경계
- hold time
- cooldown
- 빠른 연속 움직임

### Firebase
- A/B 정상 연결
- A 새로고침
- B 새로고침
- 순간 네트워크 지연
- 인터넷 잠깐 끊김/복구
- stale 상태
- write throttle

### Display
- 카메라 거울
- 멀리서 글자 가독성
- confidence on/off
- 일반/학습 모드
- portrait/landscape
- fullscreen

## 4. 인식 품질 테스트

각 동작마다 최소 다음을 확인한다.

- 서로 다른 사람
- 키 차이
- 좌우 위치 차이
- 카메라와 거리 차이
- 팔 각도 변형
- 빠른 진입
- 천천히 진입
- 부분 가림
- 옷 색/형태 변화
- 배경에 다른 학생이 지나감

기록할 지표:
- 정상 인식 여부
- 오탐 대상 클래스
- 확정까지 체감 지연
- confidence 분포
- false transition 빈도

## 5. 복도 환경 테스트

### 거리
여러 후보 거리를 실제로 측정한다.
전신이 안정적으로 프레임 안에 들어오면서 지나치게 작아지지 않는 지점을 정한다.

### 높이
카메라 설치 높이를 바꿔 다음을 확인한다.
- 저학년/고학년 키 범위
- 발끝 누락
- 머리 누락
- 팔을 위로 들었을 때 누락

### 조명
- 형광등
- 밝은 시간
- 어두운 시간
- 창문 역광
- 옆광

### 혼잡
- 뒤 학생 통과
- 옆 학생 대기
- 두 사람이 동시에 프레임 진입

초기 제품은 단일 사용자를 목표로 하므로 바닥 standing zone 등 운영적 보완도 함께 평가한다.

## 6. 성능 테스트

확인 항목:
- AI inference FPS
- 화면 렌더링 체감
- 30분 연속 동작
- 1시간 이상 연속 동작
- 발열
- 브라우저 메모리 증가
- 카메라 멈춤
- 모델 추론 지연 증가

목표는 최대 FPS가 아니라 **안정적인 반응과 장시간 지속성**이다.

## 7. 네트워크 성능

A에서 action 확정 시점과 B 표시 시점 차이를 측정한다.

초기 목표:
- 일반적인 학교 인터넷에서 체감상 즉시 반응
- 가능하면 1초 미만
- 지연 시 이전 상태를 반복적으로 흔들지 않음

Firebase에 매 inference frame을 쓰지 않는다.

## 8. 회귀 테스트

모델 또는 stabilizer 변경 시 최소 다음을 다시 확인한다.

- neutral
- one_hand_up
- hands_up
- arms_open
- sitting
- bowing
- A -> B 동기화
- stale 상태
- Pages 모델 경로

새 모델이 기존 모델보다 항상 낫다고 가정하지 않는다.
